# 数据库迁移

应用通过 `Store.MigrateWithDefaults` 在 SQLite 事务内执行版本化迁移，使用 `schema_migrations` 记录已完成版本。部署迁移入口仍为 `scripts/migrate.sh`。不要单独执行 SQL 文件来升级现有数据库：版本 3 的用户配额必须从部署配置回填，旧实例的待确认运行状态也需要在同一事务里转换。

版本 1 / 2 兼容旧版没有迁移记录的数据库。版本 3 增加多用户权限、配额、登录撤销、密码交付、审计及持久实例状态；保留旧用户 ID、密码哈希、实例归属和文件路径。旧 `expired` 实例使用内部 `legacy_expired` 标记，待核对容器后映射为实际运行或停止；旧 `disconnected` 期望继续运行。Docker 不可达不会丢失待迁移意图。重复启动不会覆盖密码或重新分配配额。

每个尚未清理完成的实例记录都占配额。删除用户的外键不级联删除实例，必须先由服务层确认容器和目录已清理。已删除实例的创建请求键保留至账号删除，防止迟到的重复请求创建替代实例。邮件记录在用户删除后去除用户关联；审计只保存操作者和目标 ID、动作与结果，不保存明文密码。

本次升级不可通过删除新增字段来安全回滚。升级前备份数据库及 profile / 下载目录，回退时使用对应版本的完整备份；不要在运行中复制非一致的 SQLite 主文件而忽略 WAL。
